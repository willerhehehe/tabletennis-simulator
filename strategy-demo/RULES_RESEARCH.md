# 技术规则研究与 demo 修订依据

研究日期：2026-09-08。核对 Table Tennis England 教练资料、PingSkills 教练答复和当前 game.mjs。本文是规则设计依据，尚未修改游戏逻辑；没有把教练定性描述当作成功率统计。以下基础矩阵默认双方使用反胶，长胶等需另立规则。

## 1. 根本问题

当前模型允许“稳妥 / 控制 / 进攻”和“上旋 / 下旋 / 不转”自由组合，实际上是在选择想要的结果，没有模拟通过什么动作做到。应该改为：来球状态与到位情况 → 可尝试的具体技术 → 执行与误判 → 回球状态。

“短下旋不能随意变成上旋”的判断成立，但“只有拧才行”不宜成为绝对限制。正手挑打也有摩擦提拉型，球低或有下旋时需要更多提拉；碰撞偏多的挑打更依赖拍型、球高。拧拉也不是无条件成功。参考：[PingSkills：两种正手挑打](https://www.pingskills.com/table-tennis-forum/two-types-of-forehand-flick)、[短下旋的挑与搓](https://www.pingskills.com/table-tennis-forum/how-to-flick-backspin-ball-2)。

## 2. 第一版技术关系表（规则提案，非穷举）

| 来球条件 | 优先保留的技术 | 典型回球 | 游戏里应表达的代价 |
| --- | --- | --- | --- |
| 短、低、下旋 | 摆短、劈长 / 搓长 | 以下旋为主；专门的变化可少转 | 摆短控制长度与高度；劈长主动给深度并准备下一板 |
| 短、低、下旋 | 反手拧拉、正手挑打 | 上旋或侧上旋；挑打可少转 | 台内到位、相应技术熟练度、抗下旋能力；重下旋时风险增加 |
| 短、不转 / 弱上旋 | 挑打、拧拉、轻触控制 | 上旋、侧上旋或少转 | 不能照搬重下旋搓接动作；控短仍需要手感 |
| 长、下旋 | 搓长、拉起下旋 | 下旋 / 上旋 | 拉起需要空间与向上摩擦，不等同普通攻球 |
| 长、上旋 | 挡、快带、反拉；合适位置削球 | 上旋体系回球；削球以下旋为主 | 借力、主动加力、切削是不同动作，吃旋转方式不同 |
| 冒高、可攻击 | 挑打或攻打 / 扣杀，取决于高度与空间 | 通常少转或上旋 | 提供更有利的攻击窗口，不直接判必杀 |

短球的搓、摆、挑以及长球起板依据：[Table Tennis England：接发球](https://newsarchive.tabletennisengland.co.uk/news/archived/return-of-serve/)。挡球、拉下旋与反拉的动作差异依据：[正手技术发展](https://newsarchive.tabletennisengland.co.uk/news/archived/developing-forehand-strokes/)。搓和削的下旋属性依据：[PingSkills：上下旋与动作](https://www.pingskills.com/table-tennis-forum/topsin-and-backspin)。

“典型回球”不能变成对现实的硬断言：搓有不转变化，挡有切挡与侧旋变化。首版未实现的特殊动作应说明“暂未收录”，不能说明“物理上不可能”。

## 3. 球需要哪些状态

建议保留离散模型，但拆分六项：横向落点、长度类别（短 / 半出台 / 长）、旋转方向、旋转强度、速度、可击球高度（低 / 普通 / 高）。击球时机与身体到位再作为球员状态。

- **短球不是第一落点靠网。** 判断依据是若不接球，球是否会在接球方台面再跳一次。半出台应在本项目明确为“预计第二跳处于端线附近的模糊区间”，避免不同教材对术语范围的差异。图上落点与长度必须分开表达。[Table Tennis England：发球与旋转](https://newsarchive.tabletennisengland.co.uk/news/archived/service-and-spin/)
- **长球不等于必须退到中台。** 接球位置还取决于时机与技术：近台挡和近台反拉是正常选择。当前 `target.y=1` 一律充当中台理想接球位，需要改成技术相关的接球区域。[正手技术发展](https://newsarchive.tabletennisengland.co.uk/news/archived/developing-forehand-strokes/)
- **质量不是速度与旋转的物理加法。** 可以保留 1–10 的游戏评价，但不能让少转自动换取更高球速，也不能让进攻必然高质量、防守必然低质量。应按技术目标评价执行：低而短的摆短、深而急的劈长都能制造压力。这是基于技术作用作出的游戏设计推导。
- **冒高应改变高度。** 当前只设 `quality=2`，并未给对方真正的高球进攻窗口。下一板可用动作与风险必须读取高度。

## 4. 身体位置和正反手

当前按来球在人物左或右扣分，无法表达侧身正手、正手位反手拧拉以及追身球。应改为：技术需要相对身体的击球空间和准备时间；跨区使用要付出额外移动 / 还原代价，不是简单禁止。

反手拧拉覆盖正手短球后，要考虑下一板还原；正手挑打可能更利于保持位置。教练有直接讨论：[PingSkills：正手挑与反手拧的取舍](https://www.pingskills.com/table-tennis-forum/about-fh-flick-vs-backspin)。

游戏提案：保留 3×5 移动盘，技术决定可接球区域；近台短球要求进台准备，远台削球要求相应空间。先不做连续人体物理。

## 5. 误判应该有方向性

| 判断与实际的差异 | 可能后果 | 需要联动的变量 |
| --- | --- | --- |
| 实际下旋强于预期 | 提拉或拍型补偿不足，容易下网 | 具体接法、旋转差、熟练度 |
| 实际不转，却按强下旋处理 | 搓接可能冒高；起板可能过高或出界 | 技术、拍型准备与击球高度 |
| 长短误判 | 进台后被顶住，或退后后够不到短球 | 剩余时间与可调整范围 |
| 横向误判 | 勉强伸手、击球空间受挤压或漏接 | 站位、正反手准备、速度 |

旋转误判与起板动作的依据：[PingSkills：拉下旋时下网](https://www.pingskills.com/table-tennis-forum/forehand-topsin-when-receiving-a-chop)、[Table Tennis England：不转变化与拉球出界](https://newsarchive.tabletennisengland.co.uk/news/archived/developing-forehand-strokes/)。表中后果是条件性风险，不是每次必然发生。

等待也不能保证识别真实旋转。以后可让等待提供更准确的长度 / 方向线索，但保留旋转估计误差；具体信息增益与时间成本需要试玩确定，现有“70% 线索、等待必然看清”没有实证标定。

技术菜单也必须遵守信息边界：预判阶段若根据隐藏旋转直接禁用某个动作，就会泄露答案。预判菜单依照可见线索提供准备方案，实际来球用于后续结算。

## 6. 胶皮和发球分类

基础矩阵先明确适用于反胶。长胶被动处理上旋可返回下旋，不能复用反胶动作同名映射；效果还依赖来球、胶皮和主动动作，不能写成所有球一律正负翻转。[PingSkills：长胶打法](https://www.pingskills.com/table-tennis-forum/playing-as-long-pimples-player)、[长胶与短胶](https://www.pingskills.com/table-tennis-forum/short-vs-long-pips)

顺逆旋转、勾手等应作为发球动作类别，与球的实际侧上 / 侧下 / 少转结果分开。动作相似造成识别难度，动作名称不应直接公开真实旋转。侧旋尚未纳入当前 demo，纳入后也不能只做“成功率减几分”，还应影响横向接球偏差。具体动作对应的可出旋转范围尚需专项核对，本文不声称已研究完全部发球技术。

## 7. 对当前代码的修订优先级

1. `act()` 的 shot 分支、`receiveChance()` 和 `botAction()` 共用具体技术关系：移除接球时任意选旋转；先收录摆短、搓长、挑打、拧拉、拉起、挡 / 快带、削球。发球另走发球方案。
2. 球长与人物纵向位置解耦；增加球高；输出旋转由技术与来球决定。确保高质量摆短不会因“防守”标签自动送机会球。
3. 将误判拆成旋转、方向、长短的不同后果；增加动作相关准备与还原成本。
4. 再扩展半出台、侧旋、胶皮与高调 / 前冲等细分，而不是先堆技能名称。每项成功率需真人试玩标定，研究资料没有给出可直接搬用的百分数。

修订后的最小验收情景：低短下旋不能用普通长球拉球流程无代价进攻；摆短生成短下旋而非任意上旋；劈长给对方长球起板窗口；拧拉能把台内球转入上旋相持且有到位代价；近台可挡长上旋；不转误判导致的冒高会影响下一板可用动作；相同可见线索不得因真实旋转不同而显示不同预判菜单。

这些是下一版的行为要求，当前自动模拟只验证流程可结束，并不证明技术关系或数值已经合理。

## 8. 后续核对：慢而转的球不能只按速度处理

PingSkills 教练在讨论低慢重上旋时强调摩擦、拍型与时机的配合，说明重上旋本身就是控制难点，不能在游戏里只给快速球增加压力。[教练原答复](https://www.pingskills.com/table-tennis-forum/mastering-the-counter-topspin-against-slow-spinny-balls)

v0.3.1 将这个关系落实到挡、快带、反拉与削球的难度；高吊拉起和拧拉也需应对重下旋。这里只引入定性关系，具体系数是可调整的桌游数值。界面暂按中档旋转强度估计，真实强度在接触后确认；尚未引入额外的强度猜测操作。
