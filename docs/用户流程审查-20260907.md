# 接发球实验：用户流程审查与改进

目标：设定同一条来球，在固定接球点比较动作误差下的上台率，并看懂各候选的拍型与挥拍。

本轮依据当前源码逐步检查。Mac 锁屏；Unity Editor 启动停留在初始化阶段，Pipeline 无可连接实例，因此没有取得本轮运行截图。以下不是已完成的视觉或真实鼠标操作验收，未使用旧截图作为新证据。

| 步骤 | 使用问题与当前状态 | 已执行改动 | 代码依据 |
| --- | --- | --- | --- |
| 1. 设发球、选接球点 | 有效来球可能被错误手动拍型阻断，流程恢复不足 | 自动搜索只要求有效来球和接球点；区分来球错误与手动接法错误，提供搜索、重选接球点或恢复示例的入口；错误时仍适配发球轨迹视角 | `PhysicsLab.Receive.cs` 的 `StartReceiveTask` / `CanEvaluateReceive`；`PhysicsLab.UI.cs` 的 `DrawResults`；`PhysicsLab.cs` 的 `FitCamera` |
| 2. 微调并测试手动动作 | 每次都搜索全部候选，成本高且容易失去手动动作的比较目的 | 新增“仅测试当前接法”，保持当前动作做同样的扰动试验；无效接触得到可导出的零分和失败原因 | `ReceiveStudy.TestCurrent`；`PhysicsLab.TestCurrentReceive`；`ExportSettings` |
| 3. 搜索、取消与重试 | 搜索开始即删除上轮结果；选中候选后重搜会把候选误作手调基线 | 新结果完成后才替换旧结果；取消、故障和完成时的取消都保留旧结果；重搜沿用原手调基线；全部失败的新结果也必须正确切换，避免统计与画面混用 | `StartReceiveTask` / `UpdateReceiveTask` |
| 4. 比较候选、观察动作 | 仅展示前五名；多个相同上台率难以分辨；手调基线只能看百分比 | 显示全部复验方案，每项附开合、侧偏及三轴速度；增加基线对照、播放回球与触球视图入口；单动作试验不再伪装成多方案比较 | `DrawReceiveCandidates` / `ActionDescription` |

## 验证

- `sh scripts/check.sh`：61 项通过，包括单动作测试与无效接触的失败报告。
- 使用已安装 Unity 6.3 的 C# 编译器、项目的实际引用与编译选项，编译运行时和 Editor 程序集：均无错误。现有 `referenceLabel` 未使用警告仍存在。

- 本轮尚未验证：新布局在小窗口的显示、真实点击 / 滚动 / 键盘焦点、取消按钮实测、屏幕阅读器支持。不可据此声称完成无障碍或视觉验收。

## 后续优先项

1. 双落点指定发球：减少反复调初速度，但需要明确固定哪些离拍参数、允许多大落点误差，并由物理模型反求。
2. 实验保存与恢复：将发球、固定接球点、胶皮、误差及动作范围作为一个整体保存，方便跨天继续研究。
3. 回球质量约束：当前上台率可能偏好托高球；如用于训练接发，应再明确过网高度、落点区域与回球速度的要求。
